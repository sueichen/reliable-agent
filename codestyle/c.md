# C 语言代码规范简洁版 (Huawei DKBA)

---

## 1. 代码总体原则

1. **清晰第一**：代码首先是给人读的，可读性高于性能（除非确定性能是瓶颈）。
2. **简洁为美**：代码越短越易理解；废弃代码及时清除；重复代码提炼为函数。
3. **与原有风格保持一致**：修改他人代码时沿用现有风格。

---

## 2. 头文件

- **原则**：头文件放接口声明，不放实现；职责单一，避免包含不必要头文件；依赖方向应朝稳定方向（产品 -> 平台 -> 标准库）。
- 每个 `.c` 应有同名 `.h` 文件。
- 禁止头文件循环依赖。
- 头文件应自包含（可独立编译），同时避免包含不必要头文件。
- 必须写 `#define` 保护符：`#ifndef XXX_H` / `#define XXX_H` / `#endif`。
- 禁止在头文件中定义变量。
- 只能通过 `#include` 使用外部接口，禁止在 `.c` 中写 `extern` 引用。
- 禁止在 `extern "C"` 中包含头文件。

---

## 3. 函数

| 规则 | 内容 |
|------|------|
| **原则** | 一个函数仅完成一件功能 |
| **规则 3.1** | 新增函数不超过 **50 行**（非空非注释） |
| **规则 3.2** | 代码块嵌套不超过 **4 层** |
| **规则 3.3** | 可重入函数避免共享变量，须用互斥手段保护 |
| **规则 3.4** | 参数合法性检查（调用者或接口函数）统一规定 |
| **规则 3.5** | 函数错误返回码必须全面处理 |
| **规则 3.6** | 高扇入，合理扇出（< 7，通常 3~5） |
| **规则 3.7** | 废弃代码（未被调用的函数和变量）及时清除 |
| **建议** | 不变参数用 `const`；参数不超过 5 个；内部函数加 `static` |

<bad
```c
void serial(void) {
    if (!Received) {           // 第1层
        switch (Buff) {        // 第2层
        case AISGFLG:
            if (...) {         // 第3层
                if (...) {     // 第4层
                    ...        // 第5层 — 超过4层！
                }
            }
        }
    }
}
```

<good
```c
void serial(void) {
    if (Received) return;
    TmoCount = 0;
    HandleBuff();
}
```

## 4. 标识符命名

| 规则 | 内容 | 示例 |
|------|------|------|
| **规则 4.1** | 项目组内统一命名风格 | Unix like / Windows like 选一种 |
| **规则 4.2** | 全局变量加 `g_` 前缀 | `g_exam` |
| **规则 4.3** | 静态变量加 `s_` 前缀 | `s_count` |
| **规则 4.4** | 禁止单字节命名变量（除 `i`/`j`/`k` 局部循环变量） | — |
| **规则 4.5** | 宏/枚举常量全大写 + 下划线 | `STATUS_READY` |
| **规则 4.6** | 宏定义不得用 `_` 开头结尾（除头文件保护符等） | — |

<good
```c
int g_error_number;           /* 全局变量 */
static int s_init_flag;       /* 静态变量 */
#define MAX_BUFFER_SIZE 1024  /* 宏常量 */
```

<bad
```c
int n;                        /* 无含义 */
int nerr;                     /* 滥用缩写 */
int gErrorNumber;             /* 风格不统一 */
```

- 使用清晰完整的单词或公认缩写（`init`/`cfg`/`msg`/`tmp` 等），不得用汉语拼音。
- 建议用"动词"或"动词+名词"命名函数：`GetCurrentDirectory()`。

## 5. 变量

- **原则**：一个变量只有一个功能；结构体功能单一，不包含不相关数据。
- **原则**：不用或少用全局变量，模块内用 `static` 隐藏。
- 防止局部与全局变量同名。
- 严禁使用未经初始化的变量作为右值。
- 首次使用前初始化，离使用点越近越好。

<good
```c
WORD DelRelTimeQue(void) {
    WORD Ret;
    WORD Locate;
    Locate = 3;
    Ret = DeleteFromQue(Locate);
    return Ret;
}
```

<bad
```c
WORD DelRelTimeQue(void) {
    WORD Locate;
    Locate = 3;
    Locate = DeleteFromQue(Locate);  /* Locate 兼具"位置"和"返回值"两种含义 */
    return Locate;
}
```

## 6. 宏、常量

| 规则 | 内容 |
|------|------|
| **规则 6.1** | 宏表达式加完备括号：`#define AREA(a, b) ((a) * (b))` |
| **规则 6.2** | 宏的多条表达式放入 `do { ... } while(0)` |
| **规则 6.3** | 使用宏时不允许参数发生变化（如 `SQUARE(a++)`） |
| **规则 6.4** | 禁止直接使用魔鬼数字，须用宏或枚举命名 |

<good
```c
#define STATUS_READY  3
#define RECT_AREA(a, b)  ((a) * (b))
#define FOO(x) do { \
    printf("arg is %s\n", x); \
    do_something(x); \
} while(0)
```

<bad
```c
if (status == 3) { ... }               /* 魔鬼数字 */
#define RECT_AREA(a, b) a * b          /* 缺少括号 */
b = SQUARE(a++);                       /* 参数自增导致的未定义行为 */
```

- **建议**：尽量用 `const` / 函数代替宏（有类型检查、可调试）。
- 宏中不使用 `return`/`goto`/`continue`/`break` 改变控制流。

## 7. 质量保证

**优先级**：正确性 > 简洁性 > 可维护性 > 可靠性 > 可测试性 > 性能 > 可移植性

| 规则 | 内容 |
|------|------|
| **规则 7.1** | 禁止内存操作越界（数组大小、字符串 `\0`、避免危险函数） |
| **规则 7.2** | 禁止内存泄漏（异常出口检查所有资源释放） |
| **规则 7.3** | 禁止引用已释放内存（释放后置 NULL，使用前判空） |
| **规则 7.4** | 防止差 1 错误（`<=` / `<` 混淆） |
| **规则 7.5** | `if...else if` 用 `else` 结束；`switch` 必有 `default` |

**安全函数替换**：

| 危险函数 | 替换为 |
|----------|--------|
| `strcpy()` | `strncpy()` + 手工加 `\0` |
| `strcat()` | `strncat()` |
| `sprintf()` | `snprintf()` |
| `gets()` | `fgets()` |

## 8. 安全性

| 类别 | 规则 |
|------|------|
| **字符串** | 确保字符串以 NULL 结束；不将不定长内容写入固定数组 |
| **整数** | 避免上溢/下溢；避免符号错误；避免截断错误 |
| **格式化** | 格式字符与参数类型/数量匹配；禁止用户输入直接做 format 串 |
| **文件 I/O** | 不用 `strlen()` 计算二进制长度；字符 I/O 返回值用 `int` |
| **命令注入** | 用 `execve()` 代替 `system()` |

<good
```c
printf("%s", user_input);     /* 安全：作为参数传入 */
snprintf(buf, sizeof(buf), "%s", user_input);  /* 安全 */
```

<bad
```c
printf(user_input);           /* 危险：格式化字符串漏洞 */
system(sprintf("any_exe %s", input));  /* 危险：命令注入 */
```

## 9. 注释

- **好代码自我解释**，不需要大量注释。写注释是解释"为什么"（why），不是重复描述"做了什么"（what）。
- 修改代码时必须同步更新注释。
- 文件头应有版权、版本、功能说明；函数声明处注释功能及用法。
- 全局变量须较详细注释（功能、取值范围等）。
- switch case fall-through 必须有注释（`/* fall through */`）。

<good
```c
/* 由于 xx 芯片可能存在写错误，需进行写后回读校验，最多重复三次 */
int time = 0;
do {
    write_reg(some_addr, value);
    time++;
} while ((read_reg(some_addr) != value) && (time < 3));
```

<bad
```c
++i;  /* increment i */    /* 无价值：重复描述代码 */
```

## 10. 排版与格式

| 规则 | 内容 |
|------|------|
| **规则 10.1** | 每级缩进 **4 个空格**（禁止 Tab） |
| **规则 10.2** | 独立程序块之间、变量说明后加空行 |
| **规则 10.3** | 一行不超过 80 列，换行加一级缩进 |
| **规则 10.4** | 一行只写一条语句 |
| **规则 10.5** | `if`/`for`/`do`/`while`/`switch`/`case`/`default` 独占一行 |
| **规则 10.6** | 双目操作符前后加空格；单目前后不加；逗号/分号后加空格 |

<good
```c
if (current_time >= MAX_TIME_VALUE) {
    a = b + c;
}
*p = 'a';
flag = !is_empty;
p = &mem;
i++;
```

## 11. 表达式

- 避免未定义运算次序：自增/自减不与复合表达式混用；函数参数不依赖求值顺序。
- 赋值语句不放入 `if` 条件中。
- 用括号明确操作顺序，不过分依赖优先级。

<good
```c
x = (a * 3) + c + d;
x = b[i] + i;
i++;                      /* 分开写，避免未定义行为 */
```

<bad
```c
x = b[i] + i++;           /* 未定义行为 */
x = func(i++, i);         /* 参数求值顺序未定义 */
if (x = y) { foo(); }     /* 赋值混入条件 */
```

---

## 12. 其他

- 使用编译器最高告警级别，消除所有告警。
- 修改后代码及时签入版本控制系统。
- 统一调测开关、日志规则。用断言记录内部假设，但不用断言处理运行时错误。
- 单元测试在编码时（或编码前）编写，关注单元行为而非实现。
- 不重定义标准库标识符；避免嵌入式汇编；使用标准语句保证可移植性。
