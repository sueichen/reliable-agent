# 安全检查清单

> 用于 `/request-review-reliable` 的安全审计阶段。参考 OWASP Top 10 + OWASP Top 10 for LLM。

## 1. 输入处理

- [ ] 所有用户输入在系统边界处验证（类型、长度、格式、范围）
- [ ] SQL 注入：参数化查询或 ORM，无字符串拼接
- [ ] NoSQL 注入：查询在构造前验证
- [ ] XSS：HTML 输出编码，Content-Security-Policy 头
- [ ] 文件上传：类型白名单、大小限制、内容验证、不在 web root 存储
- [ ] URL 重定向：白名单验证
- [ ] OS 命令注入：不使用 `exec()` / `system()` 处理用户输入

## 2. 认证与授权

- [ ] 密码使用强哈希算法（bcrypt, scrypt, argon2）
- [ ] Session 管理安全（httpOnly, secure, SameSite cookies）
- [ ] 每个受保护端点检查授权
- [ ] IDOR：用户不能访问其他用户的资源
- [ ] 认证端点有速率限制
- [ ] JWT：短过期时间、密钥轮换、签名验证

## 3. 数据保护

- [ ] 密钥在环境变量或密钥管理服务中，不在代码中
- [ ] 敏感字段在 API 响应和日志中排除
- [ ] 数据在传输中加密（HTTPS/TLS）
- [ ] 数据在静态时加密（如需要）
- [ ] PII 按适用法规处理（GDPR, CCPA 等）

## 4. 基础设施

- [ ] 安全头配置（CSP, HSTS, X-Frame-Options, X-Content-Type-Options）
- [ ] CORS 限制到特定来源
- [ ] 依赖项定期审计已知 CVE（`npm audit`, `pip audit` 等）
- [ ] 错误消息通用化（不向用户返回堆栈追踪）
- [ ] 服务账户应用最小权限原则

## 5. 供应链

- [ ] 新依赖项及其传递树检查已知 CVE
- [ ] Postinstall 脚本需要审查
- [ ] 锁文件/完整性哈希已提交
- [ ] 依赖项来自可信来源

## 6. AI/LLM 特性（如适用）

- [ ] 模型输出视为不可信输入
- [ ] 不依赖 system prompt 作为安全边界（必须用代码强制）
- [ ] 上下文窗口中无密钥或跨租户数据
- [ ] 工具/代理权限作用域化，破坏性操作需确认
- [ ] Token、速率和递归限制已设置
- [ ] Prompt Injection 防护：用户输入与系统指令分离

## 7. 日志与监控

- [ ] 日志不包含密钥、令牌、PII 或完整请求体
- [ ] 认证事件记录在审计日志中
- [ ] 异常登录模式告警
- [ ] 依赖项 CVE 通知

## 严重度分类

| 严重度 | 标准 | 行动 |
|--------|------|------|
| Critical | 可远程利用，数据泄露或完全妥协 | 立即修复，阻塞发布 |
| High | 条件利用，显著数据暴露 | 发布前修复 |
| Medium | 有限影响，需认证才能利用 | 当前 sprint 修复 |
| Low | 理论风险，纵深防御 | 下个 sprint 安排 |
| Info | 最佳实践，当前无风险 | 考虑采纳 |
