# 性能检查清单

> 用于 `/reliable-request-review` 的性能审计阶段和 `/reliable-log` 的指标设计。

## 1. 数据访问模式

- [ ] 无 N+1 查询模式（循环内查询）
- [ ] 无无限数据获取（无 LIMIT，无分页）
- [ ] 新查询有相应的数据库索引
- [ ] 批量操作优于逐行处理
- [ ] 重复的昂贵操作使用缓存
- [ ] 连接池正确配置

## 2. 算法复杂度

- [ ] 循环复杂度：无潜在的 O(n²) 或更差
- [ ] 无不必要的重复工作（重复计算值、冗余解析）
- [ ] 数据结构匹配访问模式（查找用 Map/Set 而非 array）
- [ ] 递归有基准条件和使用记忆化（如适用）

## 3. 资源使用

- [ ] 内存：大对象不持有过长时间，无内存泄漏
- [ ] 文件句柄、连接、套接字正确关闭（try-with-resources/finally）
- [ ] 大分配使用流式处理而非缓冲
- [ ] 服务账户正确关闭/清理

## 4. 并发

- [ ] 独立调用并行化（不串行等待）
- [ ] 无锁竞争或不必要同步
- [ ] 不阻塞事件循环（CPU 密集型工作使用 Worker/异步）
- [ ] 无限并发控制（信号量/速率限制）

## 5. I/O 模式

- [ ] 无不必要的磁盘 I/O
- [ ] 日志在热路径中无每条刷新磁盘
- [ ] 序列化/反序列化不在性能关键路径中

## 6. 指标设计（RED）

- [ ] **Rate**: 新端点/操作的请求计数
- [ ] **Errors**: 错误计数，按类型分类
- [ ] **Duration**: 延迟直方图，P50/P95/P99 可查询

## 8. 严重度分类

| 严重度 | 标准 | 行动 |
|--------|------|------|
| Critical | 已知高容量路径中的 O(n²)，无限内存，资源耗尽导致数据丢失风险 | 发布前修复 |
| High | 中等流量路径中的 N+1，列表端点缺少分页，无流式的大分配 | 发布前修复 |
| Medium | 次优数据结构，小量重复计算，缺少连接池 | 当前 sprint 修复 |
| Low | 微小优化机会，无测量影响的微优化 | 安排 |

## 指标诚实规则（Metric-Honesty Rule）

**绝不伪造指标数据。** 从静态源码无法测量真实的性能指标。无测量数据时必须标注：
- `[not measured]` — 每个未经测量的发现
- `potential impact` — 用此标注替代"measurement"
- 使用静态源码分析推断的性能影响，而非声称已测量
